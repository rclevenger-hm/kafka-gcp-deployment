# Security reports

Report suspected vulnerabilities privately through the repository owner's GitHub contact or GitHub private vulnerability reporting when enabled. Do not post credentials, keys, state files or sensitive logs in public issues. Provide affected versions, reproduction steps with sanitized data and impact.

This is a reference deployment with explicit production acceptance gates. See [security model](docs/security.md), [acceptance](docs/acceptance.md) and [certificate rotation](docs/runbooks/certificate-rotation.md).
